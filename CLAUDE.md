# CLAUDE.md — Планировщик (Telegram Mini App)

## О проекте
- Личный планировщик владельца в виде Telegram Mini App. Полное ТЗ владелец прислал в чате; разработка по этапам, после каждого этапа — остановка и проверка владельцем в Telegram (телефон + ноутбук).
- Владелец — новичок: объяснять простыми словами, говорить, что нажать и что проверить.
- Версия 1 — бесплатно: без сервера, без платных подписок, без Claude API.
- Токен бота НИКОГДА не попадает в код и в репозиторий.

## Устройство
- Всё в одном `index.html` (HTML + CSS + JS), библиотека `telegram-web-app.js`. Без сборщиков и сервера. Хостинг — GitHub Pages.
- Цвета — только переменные в `:root`: `--bg --bg2 --card --text --hint --link --btn --btn-text --sep --danger --ok`, недели месяца `--w1…--w5`. С версии 2 — фиксированная светлая пастель (акцент `#4b45b8`), `--tg-theme-*` не используются; `applyTheme` красит рамку Telegram в `#f5f3fb`.
- Цели `goals`: `{ items:[{id,title,color:0–6,start,due?,stim?,reward?,steps:[{id,text,done?,day?}]}] }`, цвета — `GOAL_COLORS` (кольцо / шапка / текст). Шаг с датой — задача дня `{goal, gstep}`, синхронизация как у идей (`setGoalStepDone`, `setGoalStepDay`). Цель «достигнута», когда выполнены все шаги. Круговая диаграмма — `ring(pct, color)` (SVG), её же брать для дашбордов.
- Данные — только через `Store` (`get`, `set(key, value | null)`, `keys(prefix)`); `set` сразу пишет на устройство, в облако — через 1 с. Подписка на обновления из облака — `Store.on`.
- Ключи облака: только `A-Z a-z 0-9 _ -` (двоеточие нельзя): `day_YYYY-MM-DD`, `hm_YYYY-MM`, `habits`, `recur`, `ideas`, `settings`, `check` (заметка для проверки синхронизации, этап 1). Длинные значения сами делятся на части `ключ__N` (заголовок `#parts:N`).
- Сверка: что ещё не ушло в облако (`dirty`) и новее облака — отправляется; остальное берётся из облака; ключ, которого нет в облаке и он не «грязный», — удалён на другом устройстве.
- Повторы `recur`: `{ items:[{id,text,time?,days:[0–6, пн=0],from,until?}] }` — `getRecur` / `saveRecur` / `rulesFor(iso)`; «удалить» повтор = `until` на день раньше (прошлые дни сохраняются). Отметка повтора в дне — `rdone[id]`. Дедлайн — только у разовых задач; в календаре красная точка = невыполненный дедлайн. Синяя точка — только свои задачи и планы дня (повторы не считаются, иначе точки были бы везде).
- Привычки `habits`: `{ items:[{id,name,type:'check'|'sum',per:'day'|'week'|'month',goal,hidden?}] }`; пока ключа нет — `DEFAULT_HABITS` (train, read, video, invest). Отметки `hm_YYYY-MM`: `{ marks:{ id:{ "DD": 1 | сумма } } }` — `markOf` / `setMark`; отмечать через `markHabit` (вибрация и «Цель выполнена» при достижении цели недели/месяца). Серия (`streak`) — периоды подряд с выполненной целью; текущий считается, если уже выполнен. Месяц недели во вкладке «Дела» — по четвергу. Будущие дни отмечать нельзя.
- Своя привычка — экран `habit` (`openHabit(id|null)`, ✎ у названия); скрытые — чипы внизу «Дел». Статистика месяца — экран `stats`: недели месяца = недели, чей четверг в этом месяце; % — дни с целью / прошедшие дни, недели с целью / прошедшие недели, сумма месяца / цель. Итоги недели — экран `summary` (`weekSummaryHtml`), в воскресенье те же итоги сверху вкладки «Дела».
- Идеи `ideas`: `{ items:[{id,text,cat,link?,note?,status:'new'|'plan'|'done',month?,created,steps:[{id,text,min,done?,day?}]}] }`; разделы `CATS` (go, watch, read, learn, opps). Окно идеи (экран `idea`) сохраняется само; новая идея создаётся при первом символе текста. Шаги вставляются списком (номера/маркеры в начале строки убираются).
- «Запланировать» (`proposePlan` → экран `plan` → `pSave`): месяц — первый, не занятый другой идеей «В плане» (`pickMonth`); дни — с завтрашнего, «свободные» = не больше 1 дела (`busyScore`: задачи + планы + повторы), иначе наименее занятые; по шагу в день. Шаг в календаре — задача `{idea, step, dur}`; отметка, перенос и удаление синхронизируются с идеей (`setStepDone`). Все шаги выполнены → вопрос «в архив?». Перепланирование снимает из календаря только невыполненные шаги.
- Настройки `settings`: `{ dayStart, dayEnd (часы), step (15/30/60), pomo:{work,short,long,rounds} }` — писать через `setSetting(patch)`; цели привычек в настройках правят `habits`. Заметка-проверка этапа 1 (`check`) удалена, при запуске ключ стирается.
- Помодоро — экран `pomo` (кнопка ⏱ в шапке, в ней же остаток времени, пока идёт; запуск из окна задачи — «⏱ Таймер концентрации», подпись = текст задачи). Состояние только на устройстве (`pl~pomo:<uid>`), время — от `endAt`, поэтому после сворачивания показывает верно. Конец этапа: два сигнала (WebAudio), вибрация, всплывающая подсказка; следующий этап ждёт «Старт».
- Вибрация (`haptic`): галочки и выбор — лёгкий отклик, выполненная задача / цель — «успех», конец помодоро — «успех» + сильный толчок.
- Телефон может показывать старую версию (кэш Telegram): закрыть Telegram полностью / очистить кэш / адрес кнопки в BotFather с `?v=N`. Автообновление предложено владельцу, ответа нет.
- Окно задачи — экран `task` (`openTask(iso, id, rid, text)`), поиск — экран `search` (ищет только в дневнике).
- День `day_YYYY-MM-DD`: `{ tasks:[{id,text,done,time?,deadline?}], rdone:{}, plan:{"09:30":"текст"}, diary:"", mood:0–5 }`; читать через `getDay(iso)`, писать через `saveDay(iso, d)` (пустой день удаляет ячейку). Шкала времени берёт `settings.dayStart` / `dayEnd` (часы) / `step` (мин), по умолчанию 7 / 23 / 30.
- Навигация: вкладки `nav.tab`, экраны поверх — `openScreen(name)` / `back()`; кнопка «Назад» Telegram подключена к `back()`.
- Проверка без Telegram: копия страницы с поддельным `window.Telegram.WebApp` (облако в localStorage) — тестовые файлы держать вне репозитория.
- Новые поля ввода — `font-size: 16px` (иначе iPhone приближает страницу), `spellcheck="false" autocorrect="off"`.
